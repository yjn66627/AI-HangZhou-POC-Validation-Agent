# 公开边界政策｜PUBLICATION POLICY

> 本仓库为 Public 公开仓库，采用 `PUBLIC_PARTICIPATION_MODE`。
> 公开的是**代码与文档**，不是**内部证据与凭据**。
>
> **在提交任何内容前，请先读完本文。**

---

## 一、核心原则

> **Public 的是代码和文档，不是私有评测答案、密钥凭据、内部原始证据。**

这条原则优先于任何其他考虑。
当你不确定某份内容能不能公开时：**先不公开，去 Issue 里问。**

---

## 二、可以公开的内容

| 类别 | 说明 |
| --- | --- |
| 项目代码 | 经安全审核后的源码（当前阶段暂不迁移） |
| 项目文档 | 架构、进度、方法论文档 |
| Public Schema | 对外约定的数据结构定义 |
| Public Formal Cases | 已脱敏的正式 Case 说明 |

| UI / Demo | 面向用户的界面与演示 |
| 团队分工 | 角色与职责 |
| 公开 Issue | 问题跟踪与讨论 |
| 公开测试代码 | 后续评审后允许公开的测试用例 |

---

## 三、永远不得公开的内容

以下内容**任何情况下**都不得进入本仓库，包括提交、Issue、评论、PR、Wiki、附件、截图：

### 凭据类
- 私有评测答案
- 各类密钥凭据
- 认证请求头内容
- 会话 Cookie / Session 标识
- 环境变量文件（含示例以外的真实文件）
- 腾讯元器登录信息
- Dify Token
- 回滚凭据
- 浏览器凭据
- 任何真实口令或验证码

### 证据类
- 内部原始证据
- 未脱敏的原始响应报文
- 可用于越权访问的资源标识符

### 隐私类
- 本机用户隐私信息
- 本机绝对路径
- 个人邮箱、登录账号等信息

---

## 四、提交前自检清单

提交前逐项确认，全部为「是」才可提交：

- [ ] 没有真实密钥、令牌、口令、验证码
- [ ] 没有真实环境变量文件（示例文件必须全部为假值）
- [ ] 没有内部原始证据或未脱敏响应报文
- [ ] 没有本机绝对路径（如盘符路径、用户目录路径）
- [ ] 没有个人邮箱、登录账号等身份信息
- [ ] 没有可用于越权访问的资源标识符
- [ ] 文档中的数字与结论档位，与 Decision Engine 输出一致
- [ ] 没有把"受控试运行"表述成"生产可用"

---

## 五、示例文件（.env.example）规则

`.env.example` 允许公开，但**必须全部使用假值**。

**正确**：值全部写成尖括号占位符，肉眼一看就知道要替换。

```
变量名=<在此填写你自己的值>
服务地址=<在此填写你自己的地址>
```

**错误**：写成任何长度很长、形似真实密钥或真实内部地址的字符串。

要求：
- 一律使用尖括号占位符，不得使用任何形似真实凭据的字符串
- 不得使用真实服务地址或内部域名
- 变量名可以出现，但**值必须是占位符**

> 说明：本文档本身只出现变量「名」，不出现任何变量「值」。
> 这也是本仓库通过公开安全扫描的前提。

## 七、发现泄漏怎么办

如果发现密钥或内部证据已经进入仓库：

1. **立即停止继续提交**
2. 在 Issue 中报告（**不要**在 Issue 里粘贴泄漏内容本身）
3. 由项目负责人评估：
   - 该凭据是否需要立即轮换 / 作废
   - 历史记录是否需要清理
4. 处理完成后再恢复开发

> 注意：**删除文件不等于删除历史。** 提交过的内容会保留在 Git 历史中，
> 因此凭据一旦泄漏，必须按"已泄漏"处理并轮换，而不是只删文件。
