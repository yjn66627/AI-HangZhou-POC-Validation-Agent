# 团队分工｜TEAM ROLES

> 本文件定义当前团队角色与职责边界。
> 角色是按**产出物**划分的，不是按"谁更忙"划分的。

---

## 小杨 ｜ Project Lead + Experiment Lead

**定位**：项目负责人兼实验负责人

**职责**
- 总体架构设计与技术路线决策
- Formal Experiment 设计与执行
- Runtime 与 LIVE 实验运行
- 版本治理（版本冻结、变更口径）
- 最终技术决策输出

**产出物**
- 架构文档、Formal Experiment 定义
- LIVE 实验结果与结论
- 版本治理规则

**决策权**
- 技术路线取舍
- 实验是否通过、结论档位
- 版本冻结时点

## 小林 ｜ Product / UX / Demo Lead

**定位**：产品、体验与演示负责人
（建议角色，待确认）

**职责**
- UI 设计与实现
- 产品体验梳理与优化
- 公开 Demo 搭建与维护
- 展示故事线设计（怎么讲清楚这个项目）
- 试玩反馈收集与整理

**产出物**
- 产品界面
- 公开 Demo
- 演示脚本与故事线
- 试玩反馈清单

**边界**
- 演示不得夸大结论，必须与 Decision Engine 输出档位一致
- 不得在 Demo 中展示内部证据或未脱敏数据

**定位**：Case、质量保障与研究支持
（建议角色，待确认）

**职责**

## 协作约定

| 事项 | 约定 |
| --- | --- |
| 分支 | 功能分支开发，通过 Pull Request 合入 `main` |
| 提交 | 提交信息说明"改了什么、为什么" |
| Issue | 按标签分类：`bug` / `case` / `ux` / `demo` / `docs` / `backend` / `tool-runtime` / `needs-review` |
| Review | 涉及架构与结论口径的变更需 `needs-review` |
| 安全 | 提交前执行公开边界自检，参见 [`../PUBLICATION_POLICY.md`](../PUBLICATION_POLICY.md) |

---

## 关于"结论表述"的统一口径

这是全团队最容易出错的地方，单独强调：

| 允许的表述 | 禁止的表述 |
| --- | --- |
| 集成已证明 | 可以上生产 |
| 质量已达标 | 生产可用 |
| 支持受控试运行 | 成本可控 |
| 主链路已跑通 | 稳定性已验证 |
| 5/5 重复通过 | 并发没问题 |

任何人（包括演示、README、Issue 评论）都不得越过 Decision Engine 的输出档位。
