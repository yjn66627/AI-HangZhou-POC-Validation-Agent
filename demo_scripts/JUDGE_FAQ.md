# 评委追问｜10 问 10 答

回答保持短。不提 Dify 作为最终方案，不把 SHA、`tc_`、`ta_`、Prompt Gate 塞进主叙事。结论不得越过 Decision Engine。

---

**1. 这不就是个聊天机器人吗？**

不是。页面主链是需求、候选、对照实验、Evidence、Decision。模型不能自己宣布成功，必须经过独立评估。

**2. 5/5 通过，是不是可以上生产？**

不可以。LIVE-1R 的档位是受控试运行：集成和质量已证明，成本、延迟、并发、稳定性未证明。`SUPPORT_CONTROLLED_TRIAL` 不等于 Production Ready。

**3. 你们的决策会不会永远说「再验证一下」？**

不会。质量达标且证据足够时会给出受控试运行。只有生产推荐、证据缺口或运行失败才会 `DEFER` / `INSUFFICIENT_EVIDENCE` / `HUMAN_ASSISTED`。DEMO-S 和 DEMO-N 用同一组事实回答两个不同问题。

**4. 真实工具调用做了吗？**

主演示没有把 Tool LIVE 当成已证明能力。TEST-R3 是首个 Tool 验证候选，没有真实 Tool Trace 之前不能宣布根因。主线仍在做 FIRST TOOL LIVE。

**5. 现场如果断网怎么办？**

切到同一 Case 的冻结回放，角标改为预置回放，口播说明口径与 LIVE-1R 公开摘要一致。不会静默用 Mock 冒充真实运行。

**6. 证据是不是你们自己写的？**

评估与 Decision 跟执行链分离。证据不足时 fail-closed，不允许 PASS。公开仓库只放脱敏聚合结果，不含内部原始报文。

**7. 为什么不用另一个大模型当 Baseline？**

这个产品要打的点是「结论是否外推」，不是「谁更会聊天」。错误 Baseline 就是「5/5 所以上生产」。对照的是决策纪律。

**8. 成本为什么没有数字？**

因为真实货币成本口径还没建立。未知项标记为未提供，不填 0。把空值画成 0 会伪造已测。

**9. 失败了还有结论吗？**

有。工具失败或超时输出 `HUMAN_ASSISTED`，并停止继续调工具。DEMO-F 就是这条路径。失败必须可见，不能乐观通过。

**10. 和普通 AI 咨询公司有什么不同？**

咨询给建议；我们要求候选方案进入可复核的运行和对照，再按质量、成本、延迟、风险和 Evidence 给出档位。建议可以被说圆，档位不行。
